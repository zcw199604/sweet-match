# 泡姆街机厅网页合作版

这是按《泡姆泡姆》街机厅原作玩法重做的网页版，画面为原创 Canvas 绘制，不使用官方素材。包含：

- **泡噗 2**：圆形场地中央是一颗星球，彩球从四周飘来。拖动屏幕驾驶飞船去接，彩球会粘在飞船上堆成蜂窝状；三个同色相连即消除，只靠它们挂着的球一并掉落，一次消得越多分数越高。任何彩球碰到星球，回合结束。这一款有三套主题（见下）。
- **泡噗 3**：每人一个竖井，音符从上方落下。拖动飞船接住音符，三个同色相连消除。漏掉的音符会喂给底部的怪鼠，让尖刺上升，消除可以把它压回去；碰到尖刺即出局。跟着飞船外圈收拢的节拍点「打拍」累积连击，连击越高得分倍率越高。每关 80 秒，按得分评 C～SS，达到 S 进入下一关，共三关。
- **山山兔队长大作战：泡姆狂潮**：顶部传送带不断送来 1～3 格的多色拼块。点拼块让兔子去抓，再点 12×6 场地上的格子放下（也可以按住拼块直接拖到格子上）。三个同色相连会变成泡姆，沿各自所在的行向右发射，击退从右侧走来的敌人，同时积攒能量；花 3 点能量可以用「斧头」把任意一个方块直接发射出去。敌人会啃掉挡路的方块，走到左侧防线扣一条命。五关打完进入无尽模式。

三个游戏都可以单人玩，也可以切换成同屏双人，或通过下面的局域网方式两台设备各控一个角色。

## 泡噗 2 的主题

泡噗 2 的规则完全不变，只换掉看得见的那四样东西：背景、场地、中间要守住的基地、以及驾驶的东西。棋子的形状也保持不变（它们是要被匹配的对象），只换材质。

| 主题 | 基地 | 驾驶 | 飘来的物品 | 场地 |
|---|---|---|---|---|
| 星海航路 | 带环行星 | 糖果飞碟 | 光泽彩球 | 星空重力井 |
| 深海珊瑚 | 珊瑚礁 | 潜水球（舷窗里有驾驶员，尾部冒气泡） | 气泡里的珍珠 | 海床光斑 |
| 远古部落 | 图腾柱圣坛 | 兽皮滑翔伞 | 彩绘陶珠 | 篝火土圈 |

在棋盘上方的标题栏里点缩略图即可切换，选择存在本机（`localStorage` 的 `pao-theme`），刷新后保留。主题是**每台设备各自的显示选项**：它不进 `game-core.js`，也不进联机快照，所以联机时房主和伙伴可以各看各的主题，互不影响。

要加新主题，只需在 `themes.js` 的 `THEMES` 表里加一行（基地／驾驶／背景／场地的画法键名与名词），再补上对应的画笔；`test/themes.test.js` 会检查每个主题是否配齐了五种颜色和全部字段。

## 操作

| | 触屏 / 鼠标 | 键盘 |
|---|---|---|
| 泡噗 2 | 在画布任意位置拖动，飞船跟着手指的位移走 | WASD 或方向键 |
| 泡噗 3 | 拖动移动；轻点画布或「打拍」按钮打拍 | WASD 或方向键移动，空格打拍 |
| 山山兔 | 点拼块抓取、点格子放下；「旋转」「斧头」按钮 | WASD 移动，空格抓 / 放，R 旋转，F 斧头 |

同屏双人时，泡噗 2 和泡噗 3 按画布左右半边区分两位玩家（支持两根手指同时拖动），键盘上 WASD 归玩家 1、方向键归玩家 2（回车打拍 / 抓放，Shift 旋转）。

画布使用固定逻辑坐标并按 `devicePixelRatio` 缩放。手机竖屏、手机横屏和平板上，整个棋盘和操作按钮都保持在一屏之内；横屏时按钮排在棋盘右侧。

## 本地运行

静态页面不需要构建：

```bash
npx serve .
```

浏览器打开终端显示的地址即可。也可以用任意静态服务器托管项目根目录。

## 局域网双人

Cloudflare Pages 只托管静态文件，房间码服务需要单独运行 Node 服务：

```bash
npm install
npm run lan
```

终端会打印电脑的局域网 IPv4 地址。手机和平板连接同一个 Wi‑Fi 后，打开该地址的 `8787` 端口；在“联机”弹窗中填写服务地址，房主点击“创建房间”，伙伴输入 6 位房间码加入。房主运行规则和计时，伙伴接收快照并发送操作，双方共用同一局。

如果页面部署在 Cloudflare Pages，可以在弹窗的“局域网服务地址”中填写可访问的 Node 服务地址。也可以使用“Cloudflare Pages 直连”标签，手工交换 WebRTC 的 offer/answer，不需要房间服务。

## Cloudflare Pages

创建 Pages 项目时使用本仓库：

- **Build command**：留空
- **Build output directory**：`/`（项目根目录）
- **Functions**：无需配置

`app.js`、`art.js`、`themes.js`、`game-core.js`、`style.css` 和 `index.html` 会作为静态资源直接发布。Node 局域网服务不能由 Pages 进程托管，需要在局域网电脑或另一台可访问的 Node 主机上运行。

### GitHub Actions 自动部署

仓库内的 `.github/workflows/deploy-pages.yml` 会在 `main` 分支有新提交时运行 `npm ci`、`npm test`，测试通过后使用 Wrangler 自动部署到 Cloudflare Pages，也可以在 GitHub Actions 页面手动运行。

在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 中配置：

- **Repository secret** `CLOUDFLARE_API_TOKEN`：Cloudflare API Token。Token 至少需要 Pages 编辑权限，并限制在目标账号内使用。
- **Repository variable** `CLOUDFLARE_ACCOUNT_ID`：Cloudflare 账号 ID。
- **Repository variable** `CLOUDFLARE_PAGES_PROJECT`：Pages 项目名称，必须先在 Cloudflare Pages 创建。

工作流通过 `${{ secrets.CLOUDFLARE_API_TOKEN }}` 和 `${{ vars.CLOUDFLARE_ACCOUNT_ID }}`、`${{ vars.CLOUDFLARE_PAGES_PROJECT }}` 读取这些配置，并在部署前检查是否为空。不要把 API Token 写进仓库文件或普通变量。

## 验证

```bash
npm test
npm run test:e2e
```

核心规则和局域网 API 使用 Node 测试；Playwright 使用本机 Chrome 在桌面、iPhone 13 和 iPad 视口下检查棋盘与按钮是否一屏可见，以及三个游戏各自的拖动、打拍、抓放操作。
