# 泡姆街机厅网页合作版

这是按《泡姆泡姆》街机厅原作玩法重做的网页版，画面为原创 Canvas 绘制，不使用官方素材。包含：

- **泡噗 2**：圆形场地中央是一颗星球，彩球从四周飘来。拖动屏幕驾驶飞船去接，彩球会粘在飞船上堆成蜂窝状；三个同色相连即消除，只靠它们挂着的球一并掉落，一次消得越多分数越高。飞船可以直接穿过星球，但任何彩球——飘来的，或者挂在飞船上的——碰到星球，回合结束。这一款有三套主题（见下）。
- **泡噗 3**：每人一个竖井，音符从上方落下。拖动飞船接住音符，三个同色相连消除。漏掉的音符会喂给底部的怪鼠，让尖刺上升，消除可以把它压回去；碰到尖刺即出局。跟着飞船外圈收拢的节拍点「打拍」累积连击，连击越高得分倍率越高。每关 80 秒，按得分评 C～SS，达到 S 进入下一关，共三关。另有**无尽模式**：没有倒计时和关卡，音符下落速度随时间慢慢加快（从 70 px/s 起，每秒加 0.9，封顶 260），直到碰到尖刺为止；单人的最高分记在本机。在游戏画面下方的按钮切换经典 / 无尽，选择会被记住（联机时只有经典）。
- **山山兔队长大作战：泡姆狂潮**：顶部传送带不断送来 1～3 格的多色拼块。点拼块让兔子去抓，再点 12×6 场地上的格子放下（也可以按住拼块直接拖到格子上）。三个同色相连会变成泡姆，沿各自所在的行向右发射，击退从右侧走来的敌人，同时积攒能量；花 3 点能量可以用「斧头」把任意一个方块直接发射出去。敌人会啃掉挡路的方块，走到左侧防线扣一条命。五关打完进入无尽模式。
- **方块爆破**：10×10 棋盘下方是三个待放的拼块。按住拼块拖到棋盘上松手即可放下，落点会自动吸附到最近的合法位置；触屏拖动时拼块会浮在手指上方，免得被手指挡住，即将被填满的行列会提前染成拼块的颜色。整行或整列填满就消除，一次消掉多行还有额外奖励；连续几手都能消除的话，分数倍率会一路涨。三个拼块用完自动补上新的一批，小块出现得多、大块少见，而且每批至少有一块放得下；托盘里放不下的拼块会变灰，一个都放不下时回合结束。最高分存在本机（`localStorage` 的 `pao-blast-best`）。
- **抓大鹅**：俯视一只木碗，碗里堆着 99 件 3D 物品，共 12 种（大鹅、鸡蛋、苹果、胡萝卜、玉米、南瓜、蘑菇、面包、牛奶瓶、茄子、西兰花、奶酪），它们按真实刚体物理互相压着。点一件能看见的物品，它会飞进下方 7 格暂存栏，同类会自动排在一起；凑齐 3 个同样的就消除。暂存栏塞满 7 个就失败。底下的东西够不着时点「晃一下」把整碗翻一翻。**经典模式**清空整碗即通关（累计通关次数存在 `pao-goose-wins`）；**无尽模式**限时 60 秒，每消一组加 2 秒，碗里少于 40 件时从上方补进 10 组，按消除件数计分（最高存在 `pao-goose-best`）。上次选的模式跟着账号走（见「账号设置」）。
- **三消勇者团**：带着四职业小队三消打怪，一共 50 关，分 5 章（草原、峡谷、黄昏森林、夜之城堡、熔岩荒原），每章 10 关。6×6 棋盘上有四种方块，各对应一位英雄：⚔ 战士（物理伤害，会被护甲抵掉一部分）、✦ 法师（穿透伤害，4 连溅射全场，5 连冻结敌人）、⛨ 盾卫（加护盾并嘲讽，4 连全队护盾）、✚ 牧师（治疗最虚弱的人，4 连全队治疗，5 连复活倒下的伙伴）。三个同色相连，对应英雄就出手一次，数量越多、线越长、连锁越高，效果越强。连出一条 4 个以上的直线可以多走一步（普通敌人不能连续触发，首领战可以）。每个敌人头上都预告下一招（单体、全体、穿透、吸血、自我修复），盾卫举盾时敌人会被嘲讽到他身上；倒下的英雄，他那种颜色的方块就没有效果了，所以牧师和盾卫要护好。点敌人可以换集火目标。每关通关后全队恢复一些生命、倒下的人站起来，再三选一强化（某位英雄 +25%、全队最大生命、连锁加成）。每章最后一关（第 10、20、30、40、50 关）是首领，第 40、50 关是双首领；每章第 5 关是精英对手；打败第 50 关通关。强化每层都能继续叠（每项最多 12 层，连锁加成最多 4 层），50 关共选 49 次。分数由击杀（按关卡加成）、过关奖励（含速通和存活人数）和通关奖励组成。最高分存在本机（`localStorage` 的 `pao-quest-best`）。
- **挪车接客**：一堆车挤在棋盘上，每辆车顶有一个箭头，指着它能开出去的方向。点一辆车，只要箭头前方到棋盘边缘之间没有别的车挡着，它就会开出去，停进上方五个车位之一；前面挡着车时点它只会抖一下，并把挡路的那辆标红。候车区的乘客排成一队，**只有排在最前面的人**会上车，而且只上同色的车；车坐满（小车 4 人、大巴 6 人）就开走并腾出车位。五个车位都停满、而队首的乘客又找不到自己的车，或者已经没有车能开出来，就输了；输了可以原样重试本关。一共 30 关，棋盘从 8×10 逐关长到 13×17（第 23 关起封顶），车从 14 辆到 60 多辆（每关的车数由生成时能放下多少决定，略有浮动），颜色从 3 种到 8 种，后面几关乘客的队伍也混得更乱。乘客上车时会从候车区小跳着跑向那辆车，车身弹一下，座位点点随之点亮。点「提示」会让一辆不会把局面走死的车闪一下。分数是上车的人数（每人 5 分）加过关奖励（100 × 关数），每过一关提交一次全球榜，最高分存在本机（`localStorage` 的 `pao-park-best`）。
- **倒水排序**：瓶子里叠着几层彩色液体，点一个瓶子再点另一个，把它顶上那一段同色的水倒过去：目标瓶要么是空的，要么顶上是同样的颜色，还得有空位，一次能倒几格取决于顶上有几格同色、目标还能装几格。一瓶凑满同一种颜色就会封口，飞进上方的收集架，全部收集完过关。倒不动时有四种道具，每关次数有限：回退（3 次）、加一个空瓶（1 次）、打乱未封口的液体（1 次，重新发牌会保证仍然有解）、提示一步（不限次，不扣星），另有「重来」从头倒本关。一共 50 关，从 3 种颜色、2 个空瓶开始，前两关随便倒也能过；之后颜色一点点增加到 12 种，空瓶减到 1 个，每关的最少步数也一路变长。通关按步数评星：不超过「最少步数」是三星，多 30% 以内两星，其余一星，每用一次道具少一星（最低一星）；每封一瓶 10 分，每关再按星级加 100 / 200 / 300 分。进度（关卡和总分）存在这台设备上，下次接着玩；点「重新开始」是从第 1 关开新一局。每关通关都会提交一次总分。
- **2048**：4×4 的井里，滑动屏幕（或方向键 / WASD）让所有方块一起朝那个方向滑，两个相同数字撞上就合成一个，分数加上新数字；每滑一次，空位里冒出一个 2（九成）或 4（一成）。合出 2048 算通关，之后可以继续合下去；塞满且没有能合的就结束。每局有 3 次撤销（按钮或 Z）。没打完的一局存在本机（`pao-g2048-save`），最高分在 `pao-g2048-best`，结束或重新开始时把分数提交榜单。
- **合成大西瓜**（ARCADE 15）：按住画面左右拖动瞄准，松手把水果丢进玻璃缸（电脑上鼠标移动、点击落下，或 ←→ 加空格）。两个同样的水果碰在一起合成大一级的：樱桃 → 草莓 → 葡萄 → 橘子 → 柿子 → 苹果 → 梨 → 桃 → 菠萝 → 蜜瓜 → 西瓜；只会掉下前五种，大的只能自己合。合出哪一级就加那一级的分（3、6、10……66），接连发生的合成算连击、每多一连多 2 分；两个西瓜碰到一起会一起消失，加 100 分。水果堆过红色虚线并停留两秒就结束，刚丢下去的那一个有 1 秒缓冲。没打完的一局存在本机（`pao-suika-save`），最高分在 `pao-suika-best`，结束或重新开始时提交成绩；单人游戏，上全球榜（`suika`，总分）。
- **俄罗斯方块**（ARCADE 21）：标准玩法，10 宽的场地，七种方块按 7 个一包随机发，旋转用标准的 SRS 规则（遇到墙或方块会按五组偏移依次尝试踢开），落地后还能滑动一会儿才锁定（连续滑动最多续 15 次），有落点虚影、暂存（每块限一次）、下一个预览。键盘：←→（A / D）移动并支持按住连移，↑（W / X）顺时针转，Z 逆时针转，↓（S）软降，空格直接落到底，C / Shift 暂存，P / Esc 暂停；手机用画面下方的六个按钮，点左上的「暂存」框也能暂存。计分按指南版：一次消 1～4 行 100 / 300 / 500 / 800，T-Spin（含迷你）、连击（每连 +50）、背靠背的四消或 T-Spin（×1.5）、全清奖励，都乘当前等级；软降每格 1 分、直接落到底每格 2 分。
  **难度可调**，三档各有自己的速度倍率、升级节奏、锁定延迟、预览数量和榜单（`tetris-easy` / `tetris-normal` / `tetris-hard`，按分数排名）：
  简单从第 1 级开始，速度 ×0.75，每 12 行升一级，落地后有 0.6 秒调整，预览 3 块，有虚影；
  普通从第 1 级开始，标准速度，每 10 行升一级，0.5 秒，预览 3 块，有虚影；
  困难从第 8 级开始，速度 ×1.2，每 8 行升一级，只有 0.4 秒，只预览 1 块，没有落点虚影。
  难度选择跟着账号走（设置项 `tetrisLevel`，同数独档位）；每档各存一份没打完的局，切换难度不丢进度，回来时停在「继续上次的游戏」，点继续接着玩。切到别的页面会自动暂停。
- **空中大厨**（ARCADE 22）：玩法参考 Nordcurrent 的《飞机大厨》（Airplane Chefs），代码和美术全部自己做。俯视机舱：过道两边每排 4 个座位，厨房在最后一排后面。乘客按呼叫铃点 1～3 道菜，头上的气泡里有耐心条。点乘客，厨师推着餐车走到那一排，把餐车上对得上的菜递过去（可以先递一部分，耐心回一点）；点厨房里的设备，厨师先走回厨房再操作。果汁机、甜品柜点一下直接装车；咖啡机（2.5 秒，不会糊）、烤面包机（3.5 秒）、汤锅（5 秒）、烤箱（6.5 秒）每台两格，点一下开做，做好后再点一下装车，热菜做好 7 秒还不拿就糊了，糊了要再点一下倒掉。餐车放 4 份，点餐车上的菜可以扔掉。点击会排进待办（最多 5 件），厨师按顺序走过去做，所以路线要自己规划。电脑上 1～6 对应六台设备。
  一份订单的价钱是菜价之和（橙汁 5、咖啡 8、小蛋糕 10、三明治 12、汤面 15、牛排饭 20），再加最多一半的小费，剩下的耐心越多小费越多。一关的订单（什么时候来、点什么）由关卡种子决定，重试还是同一班航班；全部订单送完或等不及走掉后飞机落地，金币达到一星目标（全部菜价的 75%）才过关，二星 105%、三星 130%，三星基本要靠小费。5 条航线共 30 关，每条航线加一道菜、座位从 3 排加到 5 排；难度按关卡数平滑上升：乘客耐心从 13 秒降到 11.5 秒（每多一道菜多 4.5 秒），来单间隔从约 3.8 秒缩到 2.2 秒，订单从 8 份加到 24 份，第 4 条航线起每单最多 3 道菜，还会有两位乘客几乎同时按铃（后期约四分之一的订单）。每条航线的第一关会放松一点，用来熟悉新菜。进度（下一关和本轮总金币）存在本机（`pao-skychef-save`），每过一关把本轮总金币提交榜单（`skychef`）。
  **升级厨房**：每关开始前的卡片上能打开商店，每项两级、按顺序买：加宽餐车（4 → 5 → 6 份）、软底跑鞋（走路快 15% / 30%）、舒适座椅（耐心 +15% / 30%）；每台会做菜的设备一级做得快 25%（热菜多保温 3 秒）、二级多一格；每道菜的食材一级卖价 +20%、二级 +40%。菜和设备要等它所在的航线解锁才能买，全部买满约 1.6 万金币，大致是一整轮的收入。过关和没过关的金币都进钱包，榜单分数只算过关的、买东西不扣；星级目标始终按原价算，所以升级会让目标更容易达到。钱包和升级属于这一轮，「重新开始」时一起清空，存档里是 `wallet` 和 `owned`（旧存档没有钱包时按已得分数补上）。
  **燃油**：每次起飞耗 10 格，油箱 50 格（满油能飞 5 趟），每 60 秒回 1 格，按时间戳计算，关掉游戏也照样回；三星过关奖励 5 格；升级商店第一行是「加油」，150 金币加 10 格，可以反复买，加满为止。油不够时起飞按钮变灰并倒计时还要等多久。燃油属于这台设备而不是这一轮（`pao-skychef-fuel`，存 `{ fuel, at }`），「重新开始」不会加满。
  **手机上看订单**：气泡和里面的菜比之前大约四成、带深色描边；餐车上已经有的菜在气泡里打绿点；厨房每台设备的铭牌上有「缺 N」角标，表示所有等待的客人还差几份这道菜（已扣掉餐车上和锅里正在做的）。
- **数独**：标准 9×9，每行每列每个 3×3 宫都填进 1～9。点一格再点下方的数字（1～9 各有自己的糖果色）；填错的数字会亮红并扣一次机会，错满 3 次本局失败（可重试同一题）。「笔记」在格子里记候选数，填对一个数时同行同列同宫里的这个候选会自动划掉；「撤销」「擦除」「提示」（直接填出一格，但用了提示的局不上榜）。简单 / 普通 / 困难三档，每题保证只有唯一解：简单（40 个已知数）和普通（32 个）只靠「只剩一个可能」的两条基本规则就能推完，困难（24 个左右）则一定需要更多技巧；每一档各自记着没做完的题（`pao-sudoku-save`），上次选的档位跟着账号走（见「账号设置」）。通关后按用时上榜。

山山兔在手机上**横过来玩**会换成宽画布：只保留传送带和棋盘，标题和状态（关卡、分数、防线、击退、能量）挪到旁边的文字里，格子比竖屏大约一半。这只是显示方式，游戏本身和联机同步不变，所以联机时一台横屏、一台竖屏也没问题；平板和电脑不受影响。

泡噗 2、泡噗 3 和山山兔都可以单人玩，也可以切换成同屏双人，或通过下面的局域网方式两台设备各控一个角色。方块爆破、抓大鹅、三消勇者团、挪车接客、倒水排序、合成大西瓜、俄罗斯方块和数独是单人游戏，不参与联机；2048 和扫雷有单独的**双人竞速**联机，扫雷另有**两人轮流的合作**玩法（见「联机对战」）。另有扫雷、斗地主、军棋翻棋版和象棋四款本地经典小游戏，军棋与象棋支持同屏双人，这四款不使用局域网房间或全球榜单，游玩时长仍计入「最近常玩」。

新增经典小游戏：

- **扫雷**：简单 9×9 / 10 雷、普通 12×10 / 20 雷、困难 16×12 / 40 雷。首次探索及周围八格安全，手机切换「插旗」标记，电脑支持右键；标旗数量匹配时点击数字快开周围，揭开全部安全格获胜。首点安全不代表每局都能无猜推完；打开「无猜」开关（默认关，只管单机）后，布雷会反复重来，直到纯推理就能从第一下扫完整盘，开关状态跟着账号走（见「账号设置」）。
- **斗地主**：一名玩家对两名基础电脑，叫分选地主、三张底牌、地主对两名农民；点牌选择，支持提示、不要、炸弹/王炸、顺子、连对、飞机和带牌组合。
- **军棋 · 翻棋版**：完整 50 子随机盖放，行营起始为空，第一枚翻棋确定阵营；支持基础电脑或同屏双人、军衔吃子、工兵排雷、炸弹、铁路、行营、大本营和夺旗。这是翻棋变体，没有布阵和四国军棋模式。
- **象棋**：红方先行，与基础电脑对弈，或切换同屏双人；标准走子、合法落点、应将、将死/困毙、和棋与悔棋。

- **泡泡龙**：开局不是随机撒色，而是按「每组 3–5 个同色、连在一起」逐组生成，长不满三个的组会退回并并到隔壁颜色，所以桌面上每个同色连通块都至少三颗，一定清得掉。顶排下压时用 `offset` 翻转来保持已有泡泡的横坐标不变。

挪车接客的玩法是「按箭头挪车解死结」加「排队接客」这一类休闲手游（Car Out / Bus Jam 一路）的通用机制，GitHub 上能找到的复刻都是 Unity 工程或没有许可证的小项目，所以这里没有参考或复用任何代码和美术：车、乘客和棋盘全部由 `park.js` 用 Canvas 现场绘制，规则是自己设计的。

三消勇者团的玩法思路参考了 [splargdotcom/atventurerer](https://github.com/splargdotcom/atventurerer)（MIT License）：方块各管一种效果、敌人提前预告下一招、连出 4 个以上多走一步。这里没有复用它的代码和画面，规则是按「四职业各配一种颜色」重新设计和实现的：它只有一个主角，这里是四个有各自生命的英雄，敌人要选谁打、盾卫的嘲讽、牧师复活、法师冻结都是新增的。英雄和怪物都是 `quest-art.js` 里手绘的原创 SVG（Q 版、统一描边与平涂阴影），各设备上看起来一致。

### 挪车接客的结构

- `park-core.js`：纯规则（造关、挡路判定、开车入位、乘客上车、胜负、提示搜索），不碰 DOM，`test/park.test.js` 直接测它。一步是 `sendCar` →（`settle` 返回这一步引起的上车 / 离站事件）→ `outcome`；界面只负责把事件一件件放出来。
- **每关一定有解**：造关时一辆辆放车，每辆车的出路必须避开已经放好的车，所以按放车的相反顺序（`witness`）一定能全部开出去；队列则是这个顺序里每几辆车（`LEVELS[].window`）的乘客打乱后拼起来，几辆车同时停着就够把它们接完，用不着超过五个车位。测试里用这个顺序跑通了每一关。
- `park.js`：Canvas 视图（候车区、五个车位、车堆），一次只播放一步，播放期间再点的车会排队等着（只保留最后一次点击）。首次点进这个游戏时才加载。
- 难度参数在 `park-core.js` 的 `LEVELS`（棋盘大小、车数、颜色数、乘客打乱的车数）。只会「先挑队首要的颜色、其余乱点」的机器人，胜率从第 1 关的约 92% 一路降到第 19 关的约一成，最后五关只剩 3%～5%；真人会看队伍提前规划，「提示」也能帮上忙。

### 三消勇者团的结构

- `quest-core.js`：纯规则（棋盘、四个英雄的技能、敌人预告与行动、关卡、强化、计分），不碰 DOM，`test/quest.test.js` 直接测它。一回合是 `swapTiles` → 反复 `resolveStep`（每一步返回它引起的事件）→ `finishMove` →（轮到敌人时）反复 `enemyStep`；界面只负责把这些事件一步步放出来。
- `quest.js`：DOM 视图。上方是横版战场（左边四位英雄、右边敌人，背景分草原 / 峡谷 / 黄昏森林 / 夜之城堡，过关时小队向右行进、背景视差卷动、下一波敌人从右侧入场），下方是 6×6 棋盘，再加强化和结算卡片。动画按 `resolveStep` / `enemyStep` 的事件逐个播放：方块交换滑动、消除爆粒子并化成光球飞向对应英雄、战士冲上去砍、法师放光弹、盾卫张护盾、牧师发治疗光、空位方块下落补齐；敌人扑击、发射穿透弹或放全体冲击波。核心事件上的 `by`（哪位英雄引起）和 `k`（敌人招式类型）就是给这些动画用的。系统开启「减少动态效果」时动画全部跳过。支持点选两格和直接滑动，点「提示」会高亮一步能成的交换。首次点进这个游戏时才加载。
- `quest-art.js`：四位英雄和十八种怪物的 SVG 造型（史莱姆、洞穴蝠、毒蘑菇、野狼、哥布林、毒蜘蛛、骷髅兵、影刃、火精灵、幽灵、黑骑士、食人魔、幼龙、岩石魔像，外加首领石像魔、蛛后、巫妖王、炎魔）。英雄朝右、怪物朝左；武器手臂（`qa-arm`）、眼睛、翅膀、披风、发光部位各自成组，CSS 负责眨眼、扇翅、飘动、呼吸光，`quest.js` 在出手时单独挥动武器手臂。造型是静态字符串，首次用到时用 `DOMParser` 解析一次后克隆。
- 难度参数在 `quest-core.js` 的 `QUEST`（`HP_START`、`HP_GROWTH`、`ATK_BASE`、`ATK_GROWTH`、`SCORE_GROWTH`）。普通关的阵容由 `waveOf` 按"每 3~4 关换一档主力怪、副手从相邻档位里轮换"生成，首领关写在 `BOSS_WAVES` 里。敌人血量按关数线性涨（1.5 起步、每关 +0.10），攻击涨得慢得多（每关 +5%），玩家靠每关一次的强化追上。用「看不到补牌、每步试遍所有交换并取均值」的贪心 bot 校准过：通关率约四成，死亡集中在第 30 关之后，每章首领那一关明显比前后难；真人预计更低。分数按关数加成（`stageValue`），满分约 8.7 万，在榜单 10 万上限之内。

### 倒水排序的结构

- `pour-core.js`：纯规则，不碰 DOM，`test/pour.test.js` 直接测它。瓶子是「从底到顶的颜色数组」；`pour` 倒水并返回事件，满瓶同色会自动封口（`seal`），`undo` / `addTube` / `shuffle` 是三个道具，`outcome` 判断 `won` / `playing` / `stuck`（倒不动但还有道具）/ `lost`。里面还有一个 A* 求解器 `solve`（启发式是瓶内相邻异色的对数，一次倒水最多消掉一对，所以不会高估，权重为 1 时得到的是最短解）和 `casualFailRate`（模拟一个只看一步的玩家，失败率越高关卡越难）。
- `pour-levels.js`：50 个现成的关卡（开局的瓶子加最短步数 `par`），是 `npm run gen:pour` 生成的，不要手改。只剩 1 个空瓶时随机发牌只有约 0.1%–4% 有解，所以关卡必须离线生成，不能在玩家手机上现算；全量生成约 1 分钟。
- **难度曲线**在 `pour-core.js` 的 `RUNGS` 表里：17 档，每档 3 关（第一档 2 关），每档写明颜色数、空瓶数，以及这一档最少步数和休闲玩家失败率的变化范围，档内平均切三段，所以每关都比上一关难一点。范围是对每种配置随机抽样得到的第 10 到第 90 百分位，保证生成得出来。2 个空瓶宽松、1 个空瓶要提前规划，所以两种交错出现。改了这张表之后要重新跑 `npm run gen:pour`，`test/pour.test.js` 会检查 `pour-levels.js` 没有过期。
- `pour.js`：Canvas 视图（360×640 的竖屏画布，收集架、瓶子和道具按钮都画在里面），首次点进这个游戏时才加载。倒水动画是源瓶移到目标瓶上方倾斜、水按体积从源瓶转到目标瓶，封口的瓶子缩小飞向收集架；系统开启「减少动态效果」时动画缩短。进度存在 `localStorage` 的 `pao-pour-save`，最高分在 `pao-pour-best`。

### 2048 和数独的结构

- `g2048-core.js`：纯规则，`test/g2048.test.js` 直接测它。方块是 `{ id, r, c, v }`，id 让视图能让同一块滑过去；`move(state, dir, rng)` 返回动画要用的事件（每块的起点终点、合并产生的新块及其两个父块、新出的块、得分），一步都动不了就返回 `{ ok: false }`，不生成新块也不计步。随机数由外部传入，测试里可以钉死新块的位置。
- `g2048.js`：Canvas 视图（360×540），滑动 110ms、合并弹一下、新块长出来；棋盘上滑动一次手指只算一步，抬起才能再滑。`window.__arcade.g2048.load(tiles)` 可以摆一个现成的局面（测试用）。
- `suika-core.js`：纯规则，`test/suika.test.js` 直接测它。自研的圆形物理，没有引入物理引擎：固定 1/120 秒一步（所以同样的落点总是同样的结果），重力、墙和地面、圆与圆的分离和冲量（半径的平方当质量）、接触摩擦，每步四轮迭代；速度很小的水果歇一会儿就睡着，一堆水果能真正静止下来，视图也就能在静止时停掉动画循环。合成在物理之后判定（每个水果每步最多合一次，连锁留给下一步）；`advance(state, 秒)` 返回这段时间里发生的事件（`merge` / `burst` / `over`）给视图放特效。随机数由外部传入，测试里可以钉死下一个水果。
- `suika.js`：Canvas 视图（360×560）：每种水果有自己的颜色、配饰（柿蒂、菠萝冠、西瓜纹……）和一张小脸；合成时新水果弹一下、溅果汁、飘出得分和连击。`window.__arcade.suika.load(fruits)` 可以摆一个现成的局面、`advance(秒)` 可以让物理快进（测试用）。
- `skychef-core.js`：纯规则，`test/skychef.test.js` 直接测它。燃油（`FUEL`、`fuelAt` 按时间补油、`burnFuel`、`addFuel`、`flightIn` 算还要等多久）、升级表 `UPGRADES`、`buy`（不改入参，返回新的等级和余额）、`kitFor`（把等级换算成这趟航班的餐车格数、步速、耐心倍率、每台设备的时间和格数、每道菜的卖价）也在这里；关卡参数由 `stageConfig` 按航线和关内序号算出（排数、订单数、来单间隔、每单最多几道菜、耐心）；订单表由种子生成；厨师的位置是「离厨房几排」，按每秒 4 排走；待办队列、设备格子的做菜 / 糊掉、上菜、小费和落地结算都在 `tick(state, 秒)` 里推进。`test/skychef-bot.js` 是一个贪心的测试玩家，测试用它保证 30 关都能过、最后几关对反应慢的人有难度。
- `skychef.js`：Canvas 视图（360×600），画面风格参考原作的官方截图：站在过道尾端往机舱里看的一点透视，每往前一排上移一截、缩小 7.5%，乘客正面坐在座位上，空乘背对我们推着餐车沿过道走（餐车台面上摆着车上的菜），下方是不锈钢厨房和蓝色台面上的餐车托盘。订单气泡是浅蓝色卡片，上面一条红底绿条的耐心条；顶部是蓝色斜切胶囊样式的关卡、金币进度（三颗星）和笑脸计数。点气泡或乘客都算点这个座位。`window.__arcade.skychef` 提供 `tapStation`、`tapSeat`、`pointOf(座位)`、`advance(秒)`、`load(关)`，测试用。
- `skychef-art.js`：全部用 Canvas 路径画的美术，没有用原作的任何图片：菜品、大头大眼的乘客（肤色、发型、衣服按座位和关卡变化，等急了皱眉、走掉时冒烟、送到时眯眼笑）、背影的空乘和餐车、订单气泡、厨房柜子和设备；每条航线一套配色（座椅、地毯、门帘）和尽头隔板上的城市壁画（上海、东京、悉尼、新加坡、巴黎和纽约）。

## 大富翁（第三方，静态版）

「灵魂锻炉」（[soulforge.glasden.top](https://soulforge.glasden.top/)）和「Achroma」（[game.unsnow.online/ach](https://game.unsnow.online/ach/)）是**别人的网页游戏**，本仓库不含它们的代码或素材，只在游戏页里用 iframe 嵌入原作者的站点（`embed-games.js`）。iframe 带 `sandbox`（不给 `allow-top-navigation`，嵌入页不能把整个街机厅跳走），允许全屏、横屏锁定、弹窗和下载。几点限制：
- 存档由浏览器按「本站 + 对方站点」分区保存，和直接打开原站玩的是两份；灵魂锻炉可以用游戏里的「导入存档」迁移。
- Achroma 的 linux.do 登录页不允许被嵌入，所以在这里不能登录、上传成绩；游戏页始终有「在原站打开」。
- 对方站点改版、下线或开始禁止嵌入，这两张卡就打不开了，本站没法兜底；不计入全球榜单，「最近常玩」只记游玩时长（焦点在游戏里时计时）。
- 测试（`test/e2e/embed-games.spec.js`）用桩页面代替外站，不依赖对方在线。

首页最后一张卡片「大富翁」是整页跳转到 `/monopoly/`，里面是 [FatPaper-1874/mine-monopoly](https://github.com/FatPaper-1874/mine-monopoly)（**GPL-3.0**）的客户端，其余十四款不是它。本仓库只放了一份补丁和固定的上游提交（`third_party/mine-monopoly/`，说明见那里的 README），不含上游源码；部署时由 workflow 现场构建到 `monopoly/`（已在 `.gitignore`，本地用 `npm run build:monopoly` 生成）。

- **只有本地派对**：免登录，同一台设备上轮流玩，可加 AI；没有联机、榜单，也不计入「最近常玩」。手机要横屏（上游自带引导）。
- **地图**：`monopoly-maps/` 里的 `.fpmap` 会随站点发布，进去点「选择地图」就能选（目前是「非常好地图」的 v0.0.11 正式版和 v0.1.0 测试版，来源和版权说明见该目录的 README）；也可以在弹窗里「导入本地文件」，支持 `.fpmap` / `.mmmap`。`.mmmap` 是加密格式，要求构建时的 `MAP_ENCRYPT_KEY` 和导出它的地图编辑器一致：默认用上游示例里的占位密钥；自己改过的话，在仓库的 Actions Variables 里设 `MONOPOLY_MAP_ENCRYPT_KEY`（16 位，本地构建时同名环境变量）。这个密钥会写进公开的前端产物，别当秘密用。
- **云端存档**：登录了首页的身份（用户名 + 密码）后，大富翁的存档会同步到服务端，换设备、换浏览器输入同一个密码就能读档（读档前先选好同一张地图）。存档仍先存在本机 IndexedDB（库名 `mine-monopoly-saves`），云端是多出来的一份：没登录、离线或站点没配数据库时就只存本机，不影响玩；上传失败的记在 `localStorage` 的 `mm-save-outbox`，下次再试。每个身份最多保留最新的 20 条；某身份在一台设备上第一次同步时，会把本机已有的存档（最新 20 条）传上去一次。接口是 `GET / POST / DELETE /api/monopoly-saves`（`functions/api/monopoly-saves.js`，规则在 `monopoly-saves-core.js`，测试见 `test/monopoly-saves.test.js`），和榜单共用同一个 D1，第一次请求时自动建表 `monopoly_saves`。注意：`pid`（密码的 SHA-256）就是凭据，知道它就能读写这个身份的存档，而存档里含游戏脚本数据，所以别把密码给不信任的人。局域网版（`npm run lan`）没有这个接口，只存本机。
- **去掉了上游的推广内容**：「给作者支持」按钮、微信 / 支付宝收款码弹窗、爱发电链接，以及 GitHub / 问卷 / B 站介绍视频按钮都不再出现。它们原本只挂在登录页，静态版跳过登录页后已经点不到，`static-mode.patch` 里把代码和收款码图片一并删掉（构建脚本还会再兜底删一次 `images/reward-qr-*`），只保留「更新日志」弹窗和版本号。
- **许可证与版权**：包含它的站点公开部署时，按 GPL-3.0 需要提供对应源码；`monopoly-maps/` 里的地图是上游作者的作品，不属于本仓库，公开发布前请确认有权这么做。只自己玩的话，建议把站点（和仓库）设为访问受限。

## 最近常玩

首页在「选择街机」上方有一块「最近常玩」：按**最后打开**的时间排序，默认显示前三个，超过三个时点「更多（N）」展开全部玩过的游戏、再点「收起」。每张卡片右上角是这个游戏的累计游玩时长（不满一分钟显示秒，之后向下取整到分钟），点卡片直接进入游戏；没玩过任何游戏时整块隐藏。

- **时长怎么算**：和活跃时长统计（见下）用同一套计时规则，只在游戏界面、页面可见、最近 30 秒内有真实操作时累计，挂机和切后台不算；不需要登录，也不依赖服务端。同一个游戏的不同模式合并成一个游戏。
- **跨设备同步**：记录按登录身份（密码派生的 `pid`）存在服务端的 `recent` 表（和榜单共用同一个 D1，第一次请求时自动建表），换浏览器输入同一个密码就能看到。服务端每个 `(pid, 游戏)` 一行：`last` 取最大值，`ms` 按增量累加，所以两台设备同时玩也不会互相覆盖。接口是 `GET /api/recent?pid=…` 和 `POST /api/recent`（`{ pid, items: [{ game, last, ms }] }`，返回合并后的汇总）。
- **本机缓存**：`localStorage` 的 `pao-recent` 是 `{ owner, games, pending }`——`games` 是上次从服务端拿到的快照，`pending` 是本机新产生、还没上报的增量，页面显示两者合并的结果。打开游戏时马上上报；游玩期间每 60 秒、回到首页、切后台 / 关页面（用 `sendBeacon`）时补报；连不上服务端时增量留在 `pending`，下次成功后补报，期间用本机缓存照常显示。缓存只属于一个身份：退出登录或换密码登录后，上一个身份的缓存会被丢弃，不会混进新身份。
- **没配数据库或在局域网版里**（`npm run lan`、`http.server`）没有 `/api/recent`，会退化成只在本机记录。
- **已知的小误差**：上报请求的响应丢了而服务端其实已经收到时，重试会让那一小段时长多算一次；页面关闭瞬间 `sendBeacon` 发不出去时会少算一小段。作为「大概玩了多久」的展示可以接受。
- 代码：`recent-core.js`（状态合并、排序、格式化、服务端处理函数和内存 / D1 存储，浏览器和服务端共用，`test/recent.test.js`）、`functions/api/recent.js`（Pages Function）、`recent.js`（浏览器端：缓存、同步和首页渲染）；`app.js` 在打开游戏时记一次，`activity.js` 的计时器每秒累计一次。

## 账号设置

扫雷的「无猜」开关、数独的难度、抓大鹅的经典 / 无尽模式会记在登录身份上，换浏览器输入同一个密码就是同样的设置。

- **服务端**：存在 `prefs` 表（和榜单共用同一个 D1，第一次请求时自动建表），每个 `(pid, 设置项)` 一行，后写为准。接口是 `GET /api/prefs?pid=…` 和 `POST /api/prefs`（`{ pid, prefs: { … } }`，返回该身份全部设置）。只接受 `PREFS` 里登记过的设置项，取值类型要对，固定选项的设置还要在 `PREF_CHOICES` 里。
- **本机缓存**：`localStorage` 的 `pao-prefs` 是 `{ owner, values, pending }`。改设置时本机立刻生效并马上上报；连不上时留在 `pending`，下次同步再报。打开页面和登录（含换身份）时拉取；进游戏时读当时的设置。缓存只属于一个身份，换人后作废。
- **旧版本迁移**：以前数独档位和抓大鹅模式存在本机的 `pao-sudoku-level`、`pao-goose-mode`。第一次拉到身份设置后，服务端还没有的项用这两个旧值补上，然后删掉旧值；迁移前进游戏也先沿用旧值。
- 代码：`prefs-core.js`（设置项登记、缓存合并、服务端处理函数和内存 / D1 存储，`test/prefs.test.js`）、`prefs.js`（浏览器端同步和迁移）、`functions/api/prefs.js`。

## 全球榜单

首页的「全球榜单」和游戏页右上角的「榜单」按钮打开榜单。每个游戏的每个模式各一份，共 14 份：泡噗 2、泡噗 3（经典 / 无尽）、山山兔、方块爆破、抓大鹅（经典按通关用时，越快越靠前；无尽按消除件数）、三消勇者团（按总分，通关或全军覆没都会提交）、挪车接客（按总分，每过一关提交一次）、倒水排序（按总分，每过一关提交一次）、2048（按总分，一局结束或重新开始时提交）、数独（简单 / 普通 / 困难各一份，按用时，越快越靠前；用过提示的局不提交）。

- **只有单人整局才上榜**：同屏双人和联机的分数是两个人的合计，不和单人比。一局结束时自动提交，结算卡片上显示全球名次；连不上榜单时只提示一句，不影响游戏。
- **每人每榜只留最好成绩**。没有账号，身份由「用户名 + 密码」决定：本浏览器还没有身份时，打开页面会先弹出一个关不掉的登录框，填用户名和密码（8~32 位字母或数字，新用户默认预填一串随机密码，也可以自己输入）。`pid` 是 `SHA-256("pao-arcade:" + 密码)`，所以**在任何浏览器输入同一个密码，就是同一个玩家、同一份成绩**；密码明文不会上传，只上传哈希。登录后密码和用户名记在本机（`pao-pw`、`pao-name`），之后不再询问；清掉站点数据或点「退出登录」后需要重新输入。没有找回功能，密码丢了就回不到这个身份。
- **登录前预览**：点「进入」时先查一次 `GET /api/player`，告诉你这个密码是「找到已有身份『X』，N 个榜单有成绩」还是「没有找到记录」（密码输错会悄悄变成一个空白新身份，这一步用来提醒），再点一次才真正进入。接口连不上时直接进入，登录本身不依赖服务端。
- **改昵称**：榜单弹窗里的「我的昵称 → 保存」会 `POST /api/player`，把这个身份在**所有榜单**上的名字一起改掉；弹窗里也能查看 / 复制密码。登录时填的用户名和已有身份不一致时，同样会同步改名。
- 旧版本的随机 `pao-pid` 不再使用，也不做迁移：老玩家登录后是一个新身份，旧成绩留在旧 pid 下。
- **没有防作弊**：成绩由浏览器上报，服务端只检查范围（`leaderboard-core.js` 里每个榜的 `min` / `max`）。想挡住批量灌水，可以在 Cloudflare 的 WAF 里给 `/api/scores`、`/api/player` 和 `/api/recent` 加速率限制规则（后者的 GET 能探测某个密码是否有成绩）。密码就是凭证：服务端不验证登录，谁知道密码谁就是这个人，所以别用 `12345678` 这类弱密码，否则会被别人撞上同一个身份。
- 代码分布：`leaderboard-core.js`（榜单定义、校验、纯 JS 的 SHA-256 与 `derivePid`、请求处理、内存 / D1 两种存储，浏览器和服务端共用）、`functions/api/scores.js` 和 `functions/api/player.js`（Pages Function）、`leaderboard.js`（浏览器端：登录门、提交成绩和弹窗）。哈希不用 `crypto.subtle`，因为 `npm run lan` 走的 http 局域网地址不是安全上下文。`test/leaderboard.test.js` 用内存存储和 `node:sqlite` 跑同一组用例，所以需要 Node 22 及以上才会跑到 D1 的 SQL，旧版本会跳过那几条。

### 部署：给 Pages 项目绑一个 D1 数据库

榜单数据存在 Cloudflare D1，部署前做一次（表会在第一次请求时自动创建，不需要迁移）：

1. 创建数据库：`npx wrangler d1 create pao-arcade-scores`（或在 Cloudflare 控制台 Workers & Pages → D1 里新建）。
2. 在 Pages 项目的 **Settings → Bindings → Add → D1 database** 里，变量名填 **`DB`**，选刚才的数据库；Production 和 Preview 环境都要加。
3. 重新部署（推送到 `main` 即可）。`wrangler pages deploy .` 会自动带上 `functions/` 目录。

没绑定时 `/api/scores` 返回 503，榜单弹窗会显示「榜单尚未配置数据库」，游戏本身不受影响。

本地调试：`npx wrangler pages dev . --d1 DB` 会在本机起一个带 D1 的 Pages 环境，榜单数据存在 `.wrangler/` 里。`npm run lan` 和 `python3 -m http.server` 没有 `/api/scores`，榜单在那里会显示连不上。

## 游玩记录（隐藏看板）

记录每个玩家（按浏览器里的 `pao-pid` 区分）在什么时间玩了哪个游戏、玩了多久，看板在 **`/ops.html`**（没有任何入口链接，`noindex`），时间一律按东八区显示。

- **怎么计时**：只在游戏界面、页面可见、最近 30 秒内有点击 / 触摸 / 指针移动 / 按键（滚轮不算）时累计；进入游戏或切回前台后要等下一次操作才开始计；切后台或挂机就暂停，中断超过 5 分钟回来算新的一段。同一个游戏的不同模式（泡噗 3 经典 / 无尽、抓大鹅经典 / 无尽）各记各的，粒度和榜单一致。
- **怎么上报**：每累计 60 秒活跃时长发一次心跳，离开游戏界面、切到后台、关页面时补发一次（`sendBeacon`）。心跳带的是累计值（`active_ms`）和距这一段开始的时长（`elapsed_ms`），服务端用自己的时钟推算开始时间，重复或乱序的心跳不会多算；不满 5 秒的误触不上报。
- **存储**：和榜单共用同一个 D1（绑定名 `DB`），表 `sessions` 第一次请求时自动创建，一行一段游玩。
- **看板**：选「今天 / 近 7 天 / 近 30 天」，看总览、各游戏时长、玩家列表（点一行只看这个人）、24 小时热力图和时间线。
- **访问令牌**：看板接口 `GET /api/admin/activity` 要求 `Authorization: Bearer <ADMIN_TOKEN>`。在 Pages 项目的 **Settings → Variables and Secrets** 里新增 Secret `ADMIN_TOKEN`（Production 和 Preview 都加），重新部署后在看板页输入同一个值，保存在这个浏览器的 `localStorage`（看板右上角「退出登录」清掉）。没配置时接口返回 503，一律不开放。令牌请用足够长的随机串，例如 `openssl rand -hex 24`。
- **首页的管理员视图**：同一个浏览器登录过看板后，首页会多一个「📊 游玩记录」按钮（显示近 7 天总时长，点击进看板），每张游戏卡片右上角显示近 7 天所有玩家在这个游戏上的总时长。数据来自同一个 `/api/admin/activity`；没有令牌的浏览器不显示也不请求，令牌失效（401）会自动清掉。见 `ops-home.js`。
- **要知道的限制**：隐藏页面不是安全措施，真正挡住别人的只有令牌；写入口 `POST /api/activity` 和榜单一样是公开的，只做范围校验，想防灌水可在 WAF 里给 `/api/activity` 加速率限制。清掉站点数据就是新玩家，同一个人换设备不会合并。D1 免费额度是每天 10 万次写入，心跳 60 秒一次，和榜单合计一般用不完。
- 代码分布：`activity-core.js`（校验、请求处理、内存 / D1 存储、看板汇总函数）、`functions/api/activity.js` 和 `functions/api/admin/activity.js`（Pages Function）、`activity.js`（浏览器端计时和上报）、`ops.html`（看板）、`ops-home.js`（首页的管理员入口和卡片时长）、`_headers`（给看板加 `X-Robots-Tag`）。`test/activity.test.js` 与榜单一样用内存存储和 `node:sqlite` 跑同一组用例。

## 联机对战（公网，房间码）

支持联机的游戏在标题栏右上角有「本地 / 联机对战」切换：**五子棋、黑白棋、国际跳棋、斗兽棋、象棋、军棋翻棋版**（两人对弈），**斗地主**（2～3 人）、**飞行棋**（2～4 人），以及 **2048、扫雷**（两人竞速；扫雷还可选两人合作）。泡噗 2、泡噗 3 和山山兔是实时游戏，走游戏页「联机」按钮里的**在线房间**（见下）。在联机页点「创建房间」会得到 6 位数字房间码和邀请链接，朋友输入房间码或打开链接就能入座；创建者先手（红方 / 黑方 / 玩家 1）。后手的棋盘会转过来，让自己的棋子在下面。

- **2048 竞速**：两人同一个开局、同一个新方块数值序列，各玩各的盘面，先合出目标方块（512 / 1024 / 2048，创建房间时选）的人赢；一方被堵死就停手，双方都走不动按分数决胜。能看到对手的盘面和分数；竞速里没有撤销，也不计入榜单。
- **扫雷竞速**：两人是同一块雷区（难度创建时选），起手由系统在中心格展开，范围不超过安全格的 25%；先扫完所有安全格的人赢，**踩雷当场判负**。对手只给进度，不给盘面（未翻开的格子里的雷和数字永远不会发到客户端）。
- **扫雷合作**：创建房间时「玩法」选「合作」。两人共用一块雷区（起手同竞速），轮流翻格子，翻开或快开都算一步，之后换人；先手随机。插旗不占回合，两人随时都能插，用来给对方提个醒。扫完所有安全格两人一起赢，谁踩雷都一起输；有人中途离开本局作废，不判输赢。
- **军棋翻棋版**：座位 0 先手，首枚翻出的棋子决定阵营。暗棋的身份和阵营只在服务端，客户端拿到的是「没翻开」，所以对手看不到你没翻的牌，也没法用开发者工具偷看。
- **斗地主**：创建房间时选「真人玩家」2 人（第三家由服务端的电脑代打）或 3 人。视角会旋转，自己永远在下方；别人的手牌只给张数，叫分阶段底牌是暗的，对局结束后才亮出。没人叫分会自动重新发牌。有人中途离开（掉线超过 60 秒或主动退出）本局作废、不判输赢。
- **飞行棋**：选 2 / 3 / 4 个真人，其余队伍由服务端的电脑代打（2 人坐红、绿对角，3 人坐红、黄、绿）。骰子在服务端掷；电脑每步间隔约 0.7 秒，看得清它做了什么。2 人局一方离开判对方获胜，3～4 人局作废。
- **再来一局 / 换边**：对局结束后棋盘上方出现提示条，任意一方可以邀请「再来一局」（座位不变）或「换边再来」（先后手互换），另一方点「同意」才开始；对方也可以「拒绝」（邀请者会收到通知）或「改为…」（提议不一致时后提的覆盖先提的，由先提的一方决定是否同意）。新的一局沿用创建时的选项（目标方块、难度），换一个新种子。2048 和扫雷竞速两边对称、斗地主 / 飞行棋 / 军棋没有可换的先后手，所以只有「再来一局」；3 人及以上的局要所有人都点同意才开始。对手已经离开、或这一局是因为弃局结束的，不能再来一局。
- **断线与退出**：掉线后客户端自动重连，座位服务端保留 60 秒（对局结束后也保留，刷新一下页面不会丢掉「再来一局」）；刷新页面会回到那一局。主动离开或超时不回来，没打完的对局判对方获胜。
- 邀请链接形如 `/?game=xiangqi&room=123456`，打开即进入对应游戏的联机页并加入房间。

### 泡噗 / 山山兔的在线房间

这三个是实时游戏，游戏本体仍然跑在**房主的浏览器**里（和局域网版一样：房主出快照、客人发操作），服务端只是个按房间码配对的中继（`server/coop-room.js`，房间名 `coop`）：房主在「联机」窗口的「在线房间」页点「创建房间」，把房间码或邀请链接（`/?coop=123456`）发给朋友，再选一个游戏；客人加入后自动进入同一局。掉线 60 秒内自动重连并重新对一次棋盘；房主离开则房间关闭。中继只转发 `hello / action / snapshot` 三种包，单包上限 32KB、每人每秒约 80 包，其余丢弃。不需要同一个 Wi‑Fi；局域网房间码和 WebRTC 两种方式照旧可用。

### 它是怎么工作的

状态**只在服务端推进**（权威服务）：客户端只提交动作，服务端用和本地游戏同一份 `*-core.js` 规则校验后再广播，所以悔棋式作弊、抢步、看对手手牌都做不到。服务端在 `server/`（Node + [Colyseus](https://github.com/colyseus/colyseus)，MIT），每个房间一份状态；浏览器端是 `net-session.js`（连接、重连、续玩，不碰 DOM）和 `online-shell.js`（大厅 / 等待 / 对局条），Colyseus 的浏览器 SDK 是 `vendor/colyseus/colyseus.js`（UMD 单文件，随站点发布，点进联机页才加载）。

适配器还有三个可选项：`seatCount(options)`（按创建选项决定真人座位数）、`auto(state)`（电脑代打：轮到没有真人的座位时房间定时调用）、`teamGame`（组队 / 合作局：有人离开时本局作废而不是判对方赢；可以是布尔值，也可以是 `(state) => 布尔值`）。

**给游戏加联机** 只要两步：在 `server/adapters/` 写一个适配器（`seats / init / canAct / apply / view / result`，回合制棋类用 `board.js` 的工厂，三行），再在 `online-games.js` 登记一行；游戏本体的 `mount` 多收一个 `online` 参数（状态来自 `online.view`，动作用 `online.send`）。规则一份、不重复。

### 本地运行

```bash
npm --prefix server ci
npm --prefix server start        # 监听 2567；不设 ALLOWED_ORIGINS 时接受任意网页来源（只用于本地）
python3 -m http.server 4173      # 另开一个终端，打开 http://127.0.0.1:4173
```

localhost / 局域网地址打开的页面默认连 `ws://<本机>:2567`，可以用 `?net=ws://主机:端口` 或 `localStorage['pao-net-server']` 改；**线上域名下这两个覆盖都不生效**，只连 `wss://wss-game.zcw.work`，免得有人发一条带 `?net=` 的链接把别人的对局引到别处。

### 部署

服务端是一个 Docker 容器，只监听宿主机回环地址，前面用 Nginx（Nginx Proxy Manager）反代并**必须打开 WebSocket 支持**：

```bash
server/deploy.sh <ssh 主机别名>      # 打包 server/ + 规则文件 → 远端构建镜像 → 重启容器 → 等到就绪才算成功
```

- `ALLOWED_ORIGINS`（逗号分隔，支持 `https://*.example.com`）默认只放行线上前端 `https://game.zcw.work`；HTTP 跨域头和 WebSocket 升级都按它校验，没带 Origin 的连接一律拒绝。要让本地页面连线上服务做调试：`ALLOWED_ORIGINS=https://game.zcw.work,http://localhost:4173 server/deploy.sh <host>`。
- 房间码由服务端生成（6 位随机数字），创建者凭一次性密钥入座，其余人必须带对房间码，所以不会有人误入或抢占别人的房间。
- 更新 SDK：`npm --prefix server ci && npm run vendor`。部署时镜像里需要的 `third_party/` 依赖（目前是象棋引擎）由 `deploy.sh` 一并打包；新游戏的核心如果引入了新的相对路径依赖，要同步加进去。

### 测试

`npm --prefix server test` 跑服务端（适配器的随机对局不变量、电脑代打、多人局作废 / 再来一局、中继房间的转发 / 限速 / 重连、视图不泄漏隐藏信息、房间码与入座校验、断线重连、弃局、再来一局 / 换边的各条分支、选项白名单、Origin 校验）。**这些测试也在 CI 里跑**（`.github/workflows/deploy-pages.yml` 的 `test` 任务，Node 22），失败会拦住部署。写服务端测试的两条规矩：端口用 `startServer(t)`（操作系统分配，不要自己挑端口），等结果用 `until(...)` 轮询（不要固定 sleep），否则在慢机器上会偶发失败；根目录 `npm test` 里的 `test/online-session.test.js` 用假 SDK 测客户端会话（重连、续玩、存储损坏）；`npx playwright test test/e2e/online.spec.js` 用两个真实浏览器上下文通过本机服务端互相对局（需要先 `npm --prefix server ci`，配置会自动起第二个 webServer）。

## 局域网双人

Cloudflare Pages 只托管静态文件，房间码服务需要单独运行 Node 服务：

```bash
npm install
npm run lan
```

终端会打印电脑的局域网 IPv4 地址。手机和平板连接同一个 Wi‑Fi 后，打开该地址的 `8787` 端口；在“联机”弹窗中填写服务地址，房主点击“创建房间”，伙伴输入 6 位房间码加入。房主运行规则和计时，伙伴接收快照并发送操作，双方共用同一局。

如果页面部署在 Cloudflare Pages，可以在弹窗的“局域网服务地址”中填写可访问的 Node 服务地址。也可以使用“Cloudflare Pages 直连”标签，手工交换 WebRTC 的 offer/answer，不需要房间服务。

- **Build output directory**：`/`（项目根目录）

### GitHub Actions 自动部署

仓库内的 `.github/workflows/deploy-pages.yml` 会在 `main` 分支有新提交时运行 `npm ci`、`npm test`，测试通过后使用 Wrangler 自动部署到 Cloudflare Pages，也可以在 GitHub Actions 页面手动运行。

在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 中配置：

- **Repository secret** `CLOUDFLARE_API_TOKEN`：Cloudflare API Token。Token 至少需要 Pages 编辑权限，并限制在目标账号内使用。
- **Repository variable** `CLOUDFLARE_ACCOUNT_ID`：Cloudflare 账号 ID。
- **Repository variable** `CLOUDFLARE_PAGES_PROJECT`：Pages 项目名称，必须先在 Cloudflare Pages 创建。

工作流通过 `${{ secrets.CLOUDFLARE_API_TOKEN }}` 和 `${{ vars.CLOUDFLARE_ACCOUNT_ID }}`、`${{ vars.CLOUDFLARE_PAGES_PROJECT }}` 读取这些配置，并在部署前检查是否为空。不要把 API Token 写进仓库文件或普通变量。
